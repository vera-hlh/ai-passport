# 工牌闯关（Passport Quest）：硬件自检与番茄钟设计

> 状态：设计草案 M0，尚未实现。本文档属于 fork 专属产品设计，位于 `docs/assets/`，不提交回上游。

## 1. 目标与非目标

**目标**

- 一个应用覆盖全部可用硬件：屏幕、背光、三键 ADC、I2C 总线、电量计、喇叭、麦克风、BLE、Wi-Fi、Flash/NVS、深睡与唤醒。
- 自检可重复、可判定、可导出：每一关都有客观判据，最终生成一份报告。
- 深睡既是测试项也是真实功能：番茄钟与自检关卡共用同一个 `power` 模块，测过就等于玩法可用。

**非目标（v1 不做）**

- NFC：NTAG213 为被动标签且不与 MCU 相连，物理上不可读写，不设关卡。
- Wi-Fi 联网与蓝牙配网：属于独立后续项目，v1 只做扫描验证射频通路。
- BLE 双机联机：独立项目，v1 只做手机可连的 GATT 读写。
- 待机电流测量：深睡电流为几十 µA 量级，软件测不出，必须用外部 USB 电流表。
- 任意 Unicode 文本：界面固定文案使用简体中文（经字体子集与缺字校验），但 SSID、AP 名、设备名等动态内容只显示 ASCII 或占位符，不直接喂给中文字体。

## 2. 板级约束（来自 `bsp_pins.h` 与实测）

| 项 | 事实 | 对本设计的影响 |
| --- | --- | --- |
| SoC | ESP32-C3，160 MHz，单核，无 PSRAM | 所有缓冲都要算堆，不能假设能开大图 |
| Flash | 8 MB，factory 分区 8.1 MB，当前 app 1.53 MB | 资源余量充足，v1 不放图片 |
| 屏 | ST7789P3 240×320，RGB565，SPI2 80 MHz，出厂反色 | 只做整屏与局部矩形刷新，避免全屏动画 |
| 背光 | LEDC PWM，GPIO21，5 kHz，10 bit | 用 `bsp_display_backlight(0..100)` |
| 三键 | 共用一个 ADC 脚（GPIO0），电压分档 `{0–150, 150–447, 447–1900} mV`，松开 ≥1900 mV | 按键判定只能靠电压窗口；短按 180 ms，长按 500 ms |
| 音频 | ES8311，I2S 全双工，16 kHz/16 bit/单声道，512 采样分块 | 录音回环是最有说服力的音频自检 |
| 电量计 | CW2017（0x63），SOC + mV；产品规格与 BSP profile 均为 500 mAh | 以 500 mAh 为准；交接文档中的 520 mAh 与此不符，不据此换算 |
| 深睡 | 定时器 + GPIO0 低电平唤醒；RTC 慢时钟为内部 RC | 时长误差必须测量，不能假设准时 |
| LVGL | 内存池 24 KB | 界面元素要少，用完后回收到零 |

## 3. 应用结构

三个入口，一套地基：

```text
main/
  app_home.c        主屏：体检 / 番茄钟 / 报告
  power.c/.h        公共：武装唤醒源、停外设、RTC 状态、唤醒原因、时长测量
  quest.c/.h        自检状态机 + 12 关
  focus.c/.h        番茄钟状态机（复用 power）
  report.c/.h       报告组装、序列化、串口导出、NVS 落盘
  ui_common.c/.h    三键导航、状态栏、字体与颜色
```

规则：

- `power` 不认识“闯关”或“番茄钟”，只接受 `(mode, duration)` 和一段 RTC 附加数据，因此两条业务线复用同一段深睡代码。
- 关卡实现只调用 BSP 公开 API（`bsp_*`），不直接碰 `esp_lcd` / `esp_codec_dev`，避免绕开板级封装。
- 纯逻辑（关卡状态机、报告序列化、剩余时间计算）不依赖 LVGL 与 ESP-IDF，放宿主测试。

## 5. 自检关卡

每关记录：开始/结束时间、判定结果、关键数值。判定为“人工确认”的关卡要求用户按键确认，避免假装客观。

| 关卡 | 硬件 | 步骤 | 客观判据 | 失败处理 |
| --- | --- | --- | --- | --- |
| L1 屏幕 | 面板 | 白/黑/红/绿/蓝整屏、16 级灰阶、1 px 边框、一行小字 | 用户确认无坏点/无偏色 | 可重看，记录“人工否决” |
| L2 背光 | LEDC | 0→100% 十档、一次呼吸、按键改档 | 用户确认无闪烁、档位可辨 | 重做一遍 |
| L3 I2C | 总线 | `bsp_i2c_scan()` | 必须同时出现 `0x18` 与 `0x63` | 直接失败，列出实际扫描结果 |
| L4 电量 | CW2017 | 读 SOC/mV，10 秒后再读 | 3000–4300 mV 且 SOC 0–100，两次差 ≤2% | 重试一次后记录 |
| L5 按键 | ADC 阶梯 | 实时显示 mV；依次单击上/下/OK、长按 OK 1 秒 | 每次读数落在对应窗口内；自动记录三档中心值 | 显示实测值供改 `BSP_BTN_MV_TABLE` |
| L6 喇叭 | ES8311 输出 | 200 Hz→8 kHz 扫频 3 秒（音量 40%），再切 5 档音量 | 用户确认有声、无破音 | 重放，允许跳过 |
| L7 麦克风 | ES8311 输入 | 录 2 秒，实时能量条 | RMS 高于开机时测得的环境噪声基线 | 提高增益后重测一次 |
| L8 回环 | I2S 全双工 | 播放 L7 的录音 | 写入字节数等于录制字节数，且用户确认可辨认 | 记录为“音频可用但回环异常” |
| L9 BLE | NimBLE | 广播 `PQ-<MAC2>` + 自定义 GATT 写特征 | 收到非空写入，且读回内容一致 | 重启广播后重试 |
| L10 Wi-Fi | STA 扫描 | 扫描并列出 AP 数与最强 RSSI | 至少扫到 1 个 AP | 重试一次，记录 RSSI |
| L11 存储 | NVS | 计数 +1，写入 16 字节随机数与时间戳 | 重启后计数连续、随机数一致 | 失败即无法保存进度 |
| L12 深睡 | RTC + GPIO0 | 短档 15 秒定时唤醒；长按 OK 中止 | 唤醒原因正确、实测时长在 ±5% 内、RTC 状态完好 | 记录唤醒原因与实际时长 |

L5 必须专门测“长按被误读成另一个键”：ADC 阶梯在触点抖动时会扫过邻键窗口，这是已知缺陷，要在报告里显式呈现，而不是掩盖。

## 6. 共用深睡模块（`power`）

### 6.1 RTC 状态

```c
#define PQ_RTC_MAGIC 0x50515553u  // 'PQUS'

typedef struct {
    uint32_t magic;
    uint32_t seq;         // 每次入睡 +1
    uint32_t mode;        // 1=quest L12，2=focus 专注，3=focus 休息
    uint32_t arg;         // 关卡号或番茄钟轮次
    uint64_t arm_us;      // 入睡瞬间的 RTC 时间
    uint64_t wake_us;     // 醒来后写入的 RTC 时间
    uint32_t checksum;    // 简单校验，避免未初始化内容被当真
} pq_rtc_t;
```

### 6.2 入睡顺序（顺序不可换）

1. 取 LVGL 锁 → 关屏（`bsp_display_backlight(0)`）→ 删页面 → 解 LVGL 锁；
2. 停止音频读写等可能访问外设的任务；
3. `bsp_battery_sleep()`；
4. `bsp_audio_sleep()`；
5. `bsp_audio_prepare_deep_sleep()`（把 I2S 引脚置高阻）；
6. `bsp_i2c_prepare_deep_sleep()`（释放共享总线）；
7. `bsp_display_prepare_deep_sleep()`（ST7789 关显示 + 睡）；
8. `bsp_button_prepare_deep_sleep(&level)`：把 GPIO0 交回数字输入并**确认按键已释放**；未释放则拒绝入睡并返回错误；
9. 武装唤醒源：`esp_sleep_enable_timer_wakeup(duration)` + `esp_deep_sleep_enable_gpio_wakeup(1ULL << BSP_BTN_GPIO, ESP_GPIO_WAKEUP_GPIO_LOW)`；
10. 写 RTC 状态 → `esp_deep_sleep_start()`。

任何一步失败都记录日志并继续（外设关不掉不应阻止入睡），但“按键未释放”是硬失败，必须回到界面提示。

### 6.3 唤醒与时间测量

深睡唤醒是复位，`app_main` 重新开始，因此启动早期第一步就是读 RTC 状态并校验 magic：

- `esp_sleep_get_wakeup_cause()` 区分 `TIMER` / `GPIO`；GPIO 唤醒只说明“GPIO0 变低”，**不说明是哪个键**，必须重新读 ADC 判定，并区分“用户主动中止”与“误触”。
- 实测睡眠时长：睡前记 `esp_clk_rtc_time()`，醒后再读一次，差值即真实睡眠时长。该 API 是否跨深睡连续，需要在 M1 用真机实测确认；若不连续，退化为“按轮次记录 + 外部表测量”，并在报告中标注不可测。
- 偏差比值 `ratchet = 实测 / 预期` 累加平均，用于下次武装定时器时补偿（限幅 ±5%），避免 25 分钟番茄钟越睡越偏。

### 6.4 番茄钟的暂停语义

深睡无法暂停 RTC 计时，所以“暂停”实现为：把已过去的时长记进 RTC，唤醒后按剩余时长重新武装。恢复时使用同一条入睡路径，避免两套代码。

## 7. 番茄钟（复用 D）

- 时长双档：**自检档 15 秒 / 5 秒**，**玩法档 25 分钟 / 5 分钟**；时长是参数，不是常量。
- 状态机：`IDLE → FOCUS(睡) → 唤醒 → 提示 → BREAK(睡) → 唤醒 → IDLE`。
- 专注中按键唤醒 → 显示剩余时间与两个选项（继续睡 / 放弃），默认 5 秒不操作则继续睡，防止误触打断。
- 完成数按天统计，写 NVS；只在一轮结束时落盘，不在每次唤醒时写 Flash。
- 报告页显示：本轮睡眠时长、预期时长、误差百分比、SOC 前后值、累计完成数。

## 8. 数据与持久化

| 数据 | 位置 | 理由 |
| --- | --- | --- |
| 入睡状态、序号、时间戳 | RTC_DATA_ATTR | 每次唤醒都要用，不能写 Flash |
| 关卡进度与判定 | NVS（`pq_quest`） | 断电保持；每关结束写一次 |
| 番茄钟完成数、设置 | NVS（`pq_focus`） | 低频写 |
| 体检报告（最新一份） | NVS（`pq_report`） | 只存最新一份与计数；NVS 分区仅 24 KB |
| 历史报告 | 串口导出到 PC | 不占用设备分区 |

### 8.1 留存策略（v1 决策）

NVS 分区只有 24 KiB（`0x9000`–`0xF000`），还要与 PHY 校准数据共用，因此**不适合存历史报告**。v1 的做法：

- NVS 只存**最新一份报告**（≤1 KB）与累计计数，保证重启、断电后仍可见；
- 历史与完整报告通过**串口导出**（文本/JSON）到 PC，界面提供“导出”入口；
- 整片烧写合并镜像会把 NVS 区间填 `0xFF`，报告与计数**可能被重置**——这是已知行为，界面上必须明确提示，不能承诺保留。

后续若确实需要“设备内保留历史、且跨整片刷机不丢”，再缩小 app 分区，并在 `0x400000` 之后新增独立 data 分区：合并镜像止于 app 末尾，不会覆盖它。该改动牵动分区表、门禁与烧录流程，按 M5 的实际需求再定，v1 不改分区表。


## 9. 界面与交互

- 240×320 竖屏，一次只显示一屏；三键：上/下移动，OK 确认，长按 OK 返回。
- 所有会访问 LVGL 的非 UI 任务必须持 `bsp_lvgl_lock()`；按键回调只做状态置位，慢操作交给任务。
- 每个页面在创建前释放上一页，离开时停掉该页所有定时器与回调，避免野指针。
- 深睡唤醒后重建界面要在 200 ms 内完成，期间显示静态提示，避免用户以为死机。

### 9.1 中文字体（v1 必做）

默认主题的 Montserrat 14/20 不含任何汉字，LVGL 内置的 Source Han Sans SC 只是子集——两者都不能靠“UTF-8 编译通过”来证明。

- **探针**：M1 先用 `CONFIG_LV_FONT_SOURCE_HAN_SANS_SC_16_CJK=y` + 一个显式指定字体的标签，确认中文能画出来。该内置子集的字符表是固定挑选的，覆盖不到全部界面文案，且实测约占 200 KB Flash，所以只能当探针、不能当正式字体；
- **正式方案（已落地）**：`tools/gen_font.py` 用 Pillow 栅格化 **Noto Sans CJK SC Regular**（SIL OFL 1.1），直接写 LVGL 的 PLAIN 4bpp 格式，16 px 与 20 px 各一份；生成后把输出的 C 解析回来，按 LVGL 的 cmap 与位图语义逐像素比对，不一致即失败。**不用 `lv_font_conv`**——它在当前 Node 下写出坏位图（见 [参考条目](../reference/shinku-chen/lvgl-cjk-font-subsets.zh_CN.md)）。
- 字符清单分两处：`main/ui_strings.h` 是全部界面文案，`tools/font_charset.txt` 是字体覆盖范围；生成的 `.c` 放 `assets/fonts/` 并加入 `main/CMakeLists.txt`。源 OTF 不入库，字族/版本/许可/SHA-256 记在 `assets/fonts/README.zh_CN.md`；
- **缺字门禁**：`tools/gen_font.py --check` 扫描 `main/ui_strings.h`，任何不在字符集里的字符报 `U+XXXX` 并让 `tools/validate.sh --static` 失败；
- **动态文本**：SSID、AP 名、设备名可能含任意 Unicode，v1 一律转换为 ASCII 或显示占位符（例如“网络 3”），不把未知字符丢给中文字体，也不静默丢字。

## 11. 测试计划

**宿主测试（无硬件）**

- `power` 的时长换算、偏差补偿限幅、暂停剩余时间计算；
- 关卡状态机：顺序推进、失败可重试、跳过只允许列明项；
- 报告序列化与反序列化往返；
- ADC 电压 → 按键映射的边界值（含窗口边界与松开态）；
- 中文字形覆盖：固定文案的码点全部命中生成字体，已知缺字反例必须失败。

**真机验收**

1. 构建并合并镜像，跑布局校验；
2. 烧录后逐关运行，记录每关数值与判定；
3. 深睡短档：确认定时唤醒、按键中止、唤醒原因、时长误差；
4. 番茄钟短档跑完整一轮（专注 + 休息）；
5. 断网/无 AP 环境下确认 L10 仍能给出“扫到 0 个”的明确结果。

**明确未验证（写入 `Unverified`）**

- 待机电流与续航：需外部 USB 电流表；
- 射频范围、穿墙与共存：需距离与干扰条件；
- 声学指标（频响、灵敏度、THD）：需仪器；
- 电池实际容量与 CW2017 profile 准确性；
- NFC：物理不可测。

## 13. 风险与待验证

1. `esp_clk_rtc_time()` 是否跨深睡连续：M1 首要验证项，决定误差测量方案。
2. 内部 RC 慢时钟的温漂：25 分钟可能偏几十秒，番茄钟需按 ±1 分钟设计，或加晶振。
3. BLE 与 LVGL、音频同时运行时的堆余量：参考实测链路约 60 KB，本应用只开两个角色，仍需实测。
4. 整片刷写会重置 NVS：报告只保留最新一份，历史依赖导出，界面必须明确提示（见 8.1）。
5. 已澄清：产品规格与 BSP profile 均为 500 mAh；交接文档的 520 mAh 不参与换算，应修正该文档。
6. 长按与深睡守卫的交互：按住键入睡会被立即唤醒，L12 与番茄钟都要显式提示。

## 14. M1 真机结论（2026-11-08）

在两台设备中的一台上实测（ESP32-C3 rev v1.1，电池 4163 mV / 98%）。

| 项 | 结果 |
| --- | --- |
| RTC 计时跨深睡 | **连续**，`esp_clk_rtc_time()` 可用于测量真实睡眠时长 |
| RC 慢时钟误差 | 请求 15 s，实测 15.39 s（**+2.61%**，26 160 ppm），漂移补偿已生效：第二次入睡自动补偿到 15.39 s |
| 定时器唤醒 / 按键唤醒 | 均正常，累计次数递增；按键被按住时拒绝入睡有效 |
| 唤醒落点 | 从自检关卡入睡后，唤醒直接回到关卡页（产品决定，保留） |
| CW2017 电量计 | 唤醒后停在睡眠态或 SOC 与电压不自洽（4.16 V 显示 0%）。新增 `bsp_battery_recover()`：RESTART/ACTIVE 后按电压区间校验 SOC，仍不自洽则重写 profile；实测约 2 秒恢复到 98% |
| 中文字体 | 内置子集覆盖 27/51；缺 21 字，作为 M2 生成子集的输入 |
| I2S | 深睡前 `channel has not been enabled yet` 是 IDF 驱动噪声，BSP 已按成功处理 |

缺字清单（M2 子集必须包含）：

```text
牌 硬 检 茄 钟 报 睡 测 试 请 松 开 按 键 唤 醒 误 败 旧 演 针
U+724C U+786C U+68C0 U+8304 U+949F U+62A5 U+7761 U+6D4B U+8BD5 U+8BF7
U+677E U+5F00 U+6309 U+952E U+5524 U+9192 U+8BEF U+8D25 U+65E7 U+6F14 U+9488
```

由此产生的两条工程决定：

- 漂移补偿的容差与限幅应保持不变：+2.61% 的实测值说明 ±5% 的窗口合适，再小会拒绝正常样本；
- 电量计的恢复逻辑属于 BSP：任何在深睡前调用 `bsp_battery_sleep()` 的应用都会遇到同样问题，`bsp_battery_recover()` 应在初始化后无条件调用（读数正常时立即返回）。

## 15. M2/M3 真机结论（2026-11-09）

| 项 | 结果 |
| --- | --- |
| L1 屏幕 | 五色 + 16 级灰阶人工确认通过 |
| L2 背光 | 10–100% 十档可辨，通过 |
| L3 接口扫描 | `0x18`、`0x63` 同时应答，通过 |
| L4 电量计 | 98% / 4162 mV，两次读数一致，通过 |
| L5 按键 | 三键单击 + 长按确定，电压落在 `bsp_pins.h` 窗口内，通过 |
| 报告页 | 六关状态 + 选中项详情，上下切换，通过 |
| NVS 持久化 | 模拟掉电后恢复，通过 |

真机暴露并修掉的问题（都已进代码）：

1. **按键测试采错时机**：`BSP_BTN_CLICK` 在抬起后触发，那时 ADC 已回到松开电压。
   电压必须用 `BSP_BTN_PRESS` 采样，CLICK/LONG 只比对事件类型。
2. **深睡时长把开机时间算进去了**：RTC 在唤醒后继续走，而代码在 `app_main` 里才读它，
   引导与初始化那约 300 ms 被当成“睡久了”，漂移补偿越垫越高，10 秒档最先超差。
   现在实测时长会扣掉这段清醒时间，并且只采纳 ±0.5% 的样本（深睡定时器与 RTC 同源时钟）。
3. **报告结果原来存在普通 RAM**：任意一次 L12 深睡都会清零。改为 RTC 内存 + NVS 双层，
   掉电才需要从 NVS 恢复。
4. **报告页载入时机**：原来要先进一次自检页才触发 NVS 载入，冷启动直接看报告是空的。
   现在 `app_main` 里 NVS 初始化后立刻载入。
5. **测试手段**：设备有电池，拔 USB 不等于断电。报告页长按下键可“模拟掉电”
   （清 RTC、留 NVS、重启），走的是与真实断电相同的恢复路径。

界面与操作约定（当前实现）：

- 报告页：上下切换、长按确定返回、长按上键清空、长按下键模拟掉电；
- 番茄钟：确定开始/继续，长按确定返回或放弃本轮，长按上键在 25/5 分钟与 1/1 分钟短档间切换；
- 报告页底部常驻提示“整片烧录会重置报告”，与 §8.1 的留存策略一致。

### 番茄钟（M4，2026-11-10 真机）

- 时长可自设：单击 ±1 分钟、双击 ±5 分钟、长按上键在专注/休息之间切换；设置存 RTC（跨深睡）并同步 NVS（跨掉电）。
- 主体时长仍然深睡，**最后 60 秒改为亮屏倒数**（`COUNTDOWN_US`）；整轮不足 1 分钟时不睡，直接倒数，便于测试。
- 最后 5 秒每秒一声短提示；到点 3 组 × 3 声（组内 70 ms、组间 700 ms）。整段波形一次性流式写出——
  “每声重新 `set_format` + `vTaskDelay` 分隔”的写法实测只响得出一组。
- 结束态显示 `00:00` 与「下一步 …」；一轮（专注 + 休息）都走完才计入「已完成」。
- 功耗取舍：最后一分钟屏幕常亮，比全程深睡多耗几十毫安；在意续航把 `COUNTDOWN_US` 调小即可，不用改状态机。
- 报告页「确定」= 把报告导出到串口，作为 NVS 之外的第二条留档路径。

### 音频关卡（M5，2026-11-12 真机）

| 关卡 | 结果 |
| --- | --- |
| L6 喇叭 | 200 Hz→8 kHz 扫频 3 秒无破音，五档音量可辨，通过 |
| L7 麦克风 | 说话时 RMS 高于门限（300），峰值正常，通过 |
| L8 回环 | 顺序回环可辨认；同时收发 1 kHz 占比 **79%**（阈值 20%），全双工成立 |

结论与经验：

- **麦克风与 I2S 全双工首次得到验证**：此前没有任何功能用到音频输入，这是整机最后一个未验证的外设；
- 2 秒 16 kHz 单声道录音需要 64 KB 堆，实际分配成功；无 PSRAM 下这是可用的上限做法（再长就该分块或落 Flash）；
- L8 的“同时收发”判据用 Goertzel 估录音里 1 kHz 的能量占比，比人耳判断稳定；实测 79% 对 20% 阈值有充足余量；
- 20 px 字号下 `同时收发 xx% 可辨认 通过` 会超出 212 px，已拆成两行，并给所有关卡结果标签加了换行模式。

### 无线与存储（M6，2026-11-12 真机）

| 项 | 结果 |
| --- | --- |
| L9 Wi-Fi 扫描 | 扫到多个 AP，最强 RSSI 正常；记录写 NVS，断电后回读一致 |
| L10 Wi-Fi 配网 | SoftAP `PQ-Setup` + 手机网页提交 SSID/密码，STA 连接成功 |
| 联网探测 | `http://connectivitycheck.gstatic.com/generate_204` 返回 `204` |
| 文件读写 | 写入 `/store/wifi_test.txt` 后读回，逐字节一致 |
| 数据分区 | 新增 4 MB SPIFFS `storage`（0x400000），app 分区缩到 4 MB |

真机踩到并修掉的三个问题：

1. **Wi-Fi 栈不能反复 init/deinit**：第二次进配网页时 `esp_netif_new` / `esp_wifi_init`
   会失败，页面直接显示“连接失败”。改为进程内只初始化一次，每次进页只开关 AP 与 HTTP。
2. **页面必须不透明**：透明的页面容器会让上一页的残留像素透出来，表现为标题上叠字。
   `pq_ui_page_create()` 现在给每个页面铺底色。
3. **页面要能感知手机**：只监听 HTTP 提交不够，手机连上热点时页面仍显示“等待手机连接”。
   现在监听 `WIFI_EVENT_AP_STACONNECTED/DISCONNECTED` 并用 500 ms 定时器刷新。

其他决定与边界：

- **BLE 关卡按用户决定跳过**，设备的两块射频里只有 Wi-Fi 被应用验证过；
- 退出配网页会关闭 STA 连接（省电，应用当前也不需要常连）；凭据存 NVS，页面显示“上次已连接”；
- **强制门户（自动弹页）未做**：目前需要手机手动打开 `192.168.4.1`；
- 分区表变化后：整片烧合并镜像仍会重置 NVS（报告），但 `storage` 分区位于 app 末尾之后，
  **文件能跨整片刷机保留**——这比“报告存 NVS”更接近长期留档。
