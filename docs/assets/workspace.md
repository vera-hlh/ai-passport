# AI Passport workspace conventions

> This file ships with the `template/app-base` branch and is the first context a new session should read.
> The `WORKSPACE.md` at the workspace root is a pointer to the same content.
> Goal: many independent applications share one installed ESP-IDF environment and one set of board
> drivers, without reinstalling anything or rebuilding the same foundations each time.

## 1. Environment (outside the workspace, machine-wide)

| Item | Value |
| --- | --- |
| ESP-IDF | `C:\esp\esp-idf-v5.5.3` |
| Tools directory | `C:\esp\.espressif` (must be set; never use the default `%USERPROFILE%\.espressif`) |
| Toolchain | riscv32-esp-elf 14.2.0, cmake, ninja, ccache already installed |
| Device | ESP32-C3, 8 MB flash, enumerates as a COM port (`VID_303A:1001`) |

Activate in every new terminal:

```powershell
$env:IDF_TOOLS_PATH='C:\esp\.espressif'
& 'C:\esp\esp-idf-v5.5.3\export.ps1'
python "$env:IDF_PATH\tools\idf.py" --version   # must print ESP-IDF v5.5.3
```

## 2. Layout

```text
C:\Dev\AI-Passport\
  WORKSPACE.md              <- pointer to this document
  ai-passport\              <- main repository (primary git worktree)
  apps\
    <app-name>\             <- one git worktree per application (own build/ and sdkconfig)
  tools\
    new_app.ps1             <- scaffolding for a new application
```

## 3. Branches and worktrees

- `main`: baseline kept in sync with upstream, no product changes;
- `template/app-base`: the **application template** — BSP, deep-sleep module, UI helpers, font
  pipeline and a minimal home screen only;
- `feature/<app-name>`: one branch per application, checked out in `apps/<app-name>`;
- tag releases as `app/<app-name>/v1` when needed.

Never copy `build/` or `sdkconfig`; let ESP-IDF generate them per worktree.

## 4. Starting an application

```powershell
.\tools\new_app.ps1 -Name my-app
# equivalent to: git worktree add apps\my-app -b feature/my-app template/app-base
# plus a README skeleton at apps\my-app\README.md
```

Build and flash:

```powershell
cd apps\my-app
idf.py set-target esp32c3       # first time only
idf.py build
idf.py -p COMx flash monitor    # or merge-bin and flash the merged image
```

Validation gate:

```powershell
.\tools\validate.sh --firmware  # build plus merged-image layout check
.\tools\validate.sh --static    # repository checks and host tests (skipped without a host compiler)
```

## 5. Reusable assets

| Asset | Location | Notes |
| --- | --- | --- |
| Board support package | `components/bsp/` | display, keys, audio, gauge, I2C — verified on hardware |
| Deep-sleep module | `main/power.c`, `power_state.c` | timer/key wake, RTC snapshot, duration measurement |
| UI helpers | `main/pq_ui.c` | colors, opaque pages, text, selected rows |
| CJK fonts | `assets/fonts/` plus `main/pq_fonts.h` | 16/20 px subsets, reproducible generator |
| Font pipeline | `tools/gen_font.py`, `font_charset.txt` | regenerate after copy changes; glyph gate included |
| Hardware facts | `components/bsp/include/bsp_pins.h` | single source of truth for pins, windows, timing |

## 6. What each application decides for itself

1. **Chinese copy**: edit `main/ui_strings.h`, recompute `tools/font_charset.txt`, regenerate fonts;
2. **Partition table**: the template defaults to a 4 MB app plus a 4 MB SPIFFS `storage` partition;
3. **NVS / SPIFFS data**: shared per device, so different applications may see each other's data;
4. **Flashing**: one application per firmware image; switching applications means reflashing, and
   flashing the merged image resets NVS.

## 7. Starting a new session

**New application** (no `apps/<name>/` yet):

```text
Workspace is C:\Dev\AI-Passport. Read WORKSPACE.md first.
I want a new application <name>: <one-line requirement>
```

Flow: read `WORKSPACE.md`, agree on the requirement and acceptance criteria, run
`tools/new_app.ps1` to create the branch, worktree and README, write the goal into the README,
then develop. **The README is generated by the scaffold; it does not exist beforehand.**

**Continuing an existing application**:

```text
Workspace is C:\Dev\AI-Passport. Read WORKSPACE.md and apps\<app-name>\README.md,
then continue <app-name>: <what to do this time>
```

**Do not fork long sessions**: they inherit a lot of unrelated history, which is expensive and
misleading. Record decisions in `apps/<app-name>/README.md` or in this directory instead.

## 8. Lifecycle of `apps/<app-name>/README.md`

| When | Who | What |
| --- | --- | --- |
| Scaffolding the app | `new_app.ps1` | skeleton with goal, status, next steps |
| After agreeing the requirement | developer or AI | one-line goal and acceptance criteria |
| End of each milestone | developer or AI | tick completed items, refresh "next" |
| Before a blocker or a new session | developer or AI | blocker, what was tried, next hypothesis |

Treat the README as a handover note for the next session, not as a product brochure.

## 9. Terminology

| Plain description | Standard term |
| --- | --- |
| one repository holding several apps | monorepo |
| one branch and one directory per app | branch-per-application with git worktrees |
| start from a template | project template / scaffolding; culturally a **golden path** |
| board drivers separated from product code | BSP plus application layer, i.e. platform/application split |
| one shared installed toolchain | pre-provisioned / shared toolchain |
| one firmware per application | product variants / build flavors |
| checks that must pass before delivery | validation gate / CI pipeline |
| short branches off the trunk | trunk-based development |
